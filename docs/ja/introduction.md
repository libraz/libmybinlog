# はじめに

libmybinlog は、MySQL と MariaDB のバイナリログ（binlog）のワイヤ形式をデコードする C++17 ライブラリです。binlog ファイルでもレプリケーション接続のイベントストリームでも、呼び出し側がすでに持っているバイト列を読み、型付きのイベントを返します。返すのはフォーマット記述、テーブルマップ、構造化された値としての行イメージ、GTID、クエリ、トランザクション境界などです。

ライブラリは `-fno-exceptions -fno-rtti` でビルドされ、仮想インターフェースを持ちません。依存は zlib だけで、zstd は任意で追加できます。

## 扱わないこと

- **レプリケーションクライアントではありません。** ネットワークのコードは含みません。接続、認証、レプリカとしての登録、`COM_BINLOG_DUMP` や `COM_BINLOG_DUMP_GTID` の送信、パケットの枠の除去は呼び出し側が行います。ライブラリはそのようなクライアントが形式の側で必要とする部品を提供します。[`GtidSet::EncodeBinary`](gtids.md) は GTID ダンプ要求に載せる GTID セットを作り、[`Decoder`](decoder.md) はファイルと同じようにダンプのストリームも読みます。
- **SQL パーサではありません。** QUERY イベントからは文のテキストとセッションのフィールドが得られますが、テキストを解析・分類はしません。したがって、ステートメントベースの binlog から得られるのは文であって行ではありません。
- **表示用の層ではありません。** 値はワイヤ上の形のまま返ります。TIMESTAMP はエポック秒、DECIMAL は正確な 10 進テキスト、ENUM は序数、文字データは列の文字セットのまま変換せず、JSON はサーバーのバイナリ形式です。ツールでサーバー自身のテキスト表現が必要なときは、`format.h` と `json.h` の関数で描画します（[値](values.md)）。
- **変更データキャプチャのポリシーではありません。** [イベントの扱い](disposition.md)と[サーバー設定の規則](server-settings.md)は、データを失ってはならない読み手のためにイベントと設定を分類します。分類をどう使うかは呼び出し側が決めます。

## 2 つの層

公開 API は、同じコードの上に 2 つの層を持ちます。

| 層 | 入口 | 使う場面 |
|---|---|---|
| 高レベル | `mybinlog::Decoder` | バイト列（ファイル、または任意に分割されたストリーム）があり、型付きのイベントを 1 つずつ取り出したいとき。 |
| 低レベル | イベント単位の free 関数: `ParseEventHeader`、`ChecksumTracker`、`ParseTableMapEvent`、`DecodeRowsEvent` など | イベントの枠を自分で切り出すとき、1 つの段階だけを使うとき、デコーダが公開していない制御が要るとき。 |

デコーダは pull 型のループです。`Feed()` でバイトを追加し、`Next()` が次の完全なイベントか `kNeedMoreData` を返します。内部では、ファイルのマジックを読み飛ばし、FORMAT_DESCRIPTION イベントごとにチェックサムの方式を追い、サーバーの種類を判定し、テーブル ID から TABLE_MAP への対応を保持し、圧縮イベントを展開し、行イベントをデコードします。どの段階も公開の低レベル関数で、[低レベル API](low-level-api.md) で説明しています。

## binlog の概要

binlog はイベントの並びです。どのイベントも 19 バイトの共通ヘッダで始まり、型コード、長さ、サーバー ID を持ちます。ファイルは 4 バイトのマジックナンバーと FORMAT_DESCRIPTION イベント（FDE）で始まります。FDE はサーバーの版を示し、ファイル内の以降の全イベントが CRC32 のトレーラで終わるかどうかを宣言します。

行ベースのログでは、データの変更は TABLE_MAP イベントと、それに続く 1 つ以上の行イベントとして届きます。TABLE_MAP はテーブルを記述して数値のテーブル ID を割り当て、行イベントはその ID を参照します。行イベントは行イメージを持ちます。INSERT と DELETE では行ごとに 1 つ、UPDATE では行ごとに変更前と変更後の組です。行イメージは TABLE_MAP の列の型に従ってデコードするので、直前の TABLE_MAP なしに行イベントは読めません。

トランザクションは位置イベント（MySQL の GTID イベント、または MariaDB の GTID イベント）で始まり、XID イベントか COMMIT のクエリで終わります。各ページで使う用語は[用語集](glossary.md)にまとめています。

## 規約

- 失敗しうる関数はすべて `mybinlog::Status` を返し、結果は末尾の出力ポインタに書きます。失敗したときは、ドキュメントに別の記載がない限り出力に触れません。例外を投げる関数はありません。[エラーと検証](errors-and-validation.md)を参照してください。
- 入力は `(const uint8_t* data, size_t size)` の組です。イベント本体のパーサは、イベントのヘッダ、ヘッダの後ろの本体、チェックサムのトレーラを除いた本体の長さを受け取ります。
- free 関数は再入可能です。`Decoder` と `ChecksumTracker` は 1 つのストリームに 1 つ使い、同時には 1 つのスレッドからだけ使います。
- すべて名前空間 `mybinlog` にあり、`#include <mybinlog/mybinlog.h>` で全公開ヘッダを読み込めます。

1.0 より前は、マイナーリリースで API が変わることがあります。
